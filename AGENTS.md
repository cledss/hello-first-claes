# AGENTS.md — Hello Claes (SecondSelf)

Hello Claes implements SecondSelf: personal AI representatives communicating over MCP.
Second Claes represents First Claes, the human principal.

## Source of truth

- **GitHub `cledss/hello-first-claes`, branch `main`, is the source of truth.**
- `main` is two-way synced with the Lovable project `dcc73415-fa34-4d11-8ee5-a60ec494b90e`.
  Lovable is the synced preview/hosting surface; do no routine development there.
- Every change goes through a small, reviewable pull request. No direct pushes to `main`,

## Stack and layout

- TanStack Start (React 19, SSR) + Vite 8, Tailwind CSS v4, shadcn/ui (Radix), TypeScript strict.
- Build output: Cloudflare Workers via Nitro. `@lovable.dev/vite-tanstack-config` wires the
  Vite plugins; do not add tanstackStart/react/tailwind/tsconfig-paths plugins manually.
- Package manager: **bun** (`bun.lock`; `bunfig.toml` has a 24h release-age guard).
  `npm install` crashes on the `overrides` block; use `bun install`.

## Access model

| Level | Who | How granted |
| --- | --- | --- |
| 0 | Anonymous visitor | Public introduction; temporary anonymous Auth account can leave one message and read its receipt. |
| 1 | Verified registered user | Automatically after verified registration; persistent magic-link login with seven-day client maximum. |
| 2+ | Trusted people/agents | Only by explicit, authenticated approval from First Claes. |

## Security requirements

- **All authorization is enforced server-side** (server functions / database policies).
  Client-side checks are UX only.
- Never trust a level, role or principal claimed by the client or by a calling agent;
  derive it from the verified session/token on the server.
- Level 2+ grants must record who approved them and when, and must be revocable.
- No secrets in the repo. Server-only secrets live in the hosting environment; only
  `VITE_*` publishable values may reach the browser.
- No mock auth, fake backend or fake success states. The "Request access" form stays
  disabled until a real, server-backed flow ships.
- MCP endpoints must authenticate the calling agent and check an explicit grant before
  executing any tool. Default deny.
- Keep the CSRF middleware in `src/start.ts` for server functions.

## Acceptance criteria (every PR)

1. `bunx tsc --noEmit`, `bun run lint`, `bun run test` and `bun run build` all pass.
2. Landing-page copy and portrait are unchanged unless the PR is explicitly about them.
3. Any new protected capability has a server-side authorization check and a test showing
   an under-privileged caller is rejected.
4. No secrets, credentials or personal data committed.
5. The PR description says what changed, how it was verified, and any step a human must do.
